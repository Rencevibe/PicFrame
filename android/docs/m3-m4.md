### Layout report (input to D2)

The whole 1280×800 design is scaled uniformly to fit the screen. A 64-unit touch target needs to be at least 7.6 mm, which is Android's 48 dp.

| Screen | Scale | 64-unit target | ≥ 48 dp? | Side bars |
|---|---|---|---|---|
| 10.1" tablet 1280×800 | 1.00 | 10.9 mm | yes | 0 |
| 10.5" tablet 1920×1200 | 1.50 | 11.3 mm | yes | 0 |
| 11" tablet 2560×1600 | 2.00 | 11.8 mm | yes | 0 |
| 8" tablet 1280×800 | 1.00 | 8.6 mm | yes | 0 |
| 6.7" phone 2400×1080 | 1.35 | 5.6 mm | **no** | 336 px |
| 6.1" phone 2340×1080 | 1.35 | 5.2 mm | **no** | 306 px |

**What this means for D2:** with the current layout, tablets of 8" and up meet the touch-target rule. Phones don't: their targets come out at about 5–6 mm, and the sides are letterboxed. Supporting phones would need a different layout.

### What M3 built

**Data (`data/`):**

| File | What it does |
|---|---|
| `DocumentTree` + `SafTree` | Reads the folder picked through the Storage Access Framework (D3). Hidden folders are skipped. |
| `PhotoSource` | Scans the folder and hands photos to the shuffle queue. An unreadable folder counts as empty. |
| `ImageCache` | Fixes EXIF orientation, decodes with sampling, and checks the pixel limit before decoding. Builds the fill crop or the fit layout with a blurred, dimmed backdrop. Writes JPEG through a temporary file, with LRU eviction and a record of bad files. Also checks that a JPEG is complete (see deviation 3). |

**UI (`ui/`):**

| Part | What it does |
|---|---|
| `Theme` | Colour tokens, the contrast pairs, and the bundled Inter and Atkinson Hyperlegible fonts. |
| `Ink` | Text helpers: anchored text, fitting with an ellipsis, fixed-width digit cells. |
| `Icons` | Original vector icons (D4), drawn in code. |
| `Widgets` | Button, toggle, stepper, segmented control, day chip. Each is drawn and returns its touch target. |
| `Screens` | Dashboard, Photo, Alarm, Night clock, Dark. |
| `SettingsScreens` | Main Settings page, the new "More settings" (Frame) page (G9), and first-run setup. |
| `Slideshow` | Preloads the next photo, fades between photos, and keeps Prev/Next history. Images are cached at the screen's real pixel size. |
| `FrameScreen` | Draws the 1280×800 design canvas scaled to fit, handles touch (pressed on finger-down, action on release inside), and lays an accessibility overlay of one node per touch target over the canvas. |

### M2 deferred config cases, now ported

`SettingsRepositoryTest` covers 5 of the 7 storage cases deferred from M2:
- a corrupt store gives defaults and a banner
- a failed save keeps the previous file (directory made read-only)
- an invalid main file falls back to the backup
- invalid bytes fall back to the backup, then to defaults
- a backup-write failure keeps the previous file

The Pi's two directory-fsync cases have no direct equivalent. The main file relies on DataStore's own atomic write. The backup file uses fsync plus rename, checked by `backupIsWrittenAtomically`. That substitution is **not** counted as equivalent; see the M2 review in `m2-domain.md`.

## Deviations from the plan

| # | Deviation | Why |
|---|---|---|
| 1 | Screenshot tests use Robolectric's native-graphics rendering, not Roborazzi or Paparazzi (plan §4) | Screens are drawn straight to a bitmap, and the comparison is against the mockups, not recorded goldens. This needs one dependency (Robolectric, which Roborazzi requires anyway) instead of two. |
| 2 | Robolectric runs the tests on API 35, not 36 (`robolectric.properties`) | Robolectric's API 36 runtime needs Java 21, and the pinned toolchain is JDK 17 (V5). The app still targets API 36. |
| 3 | A JPEG must reach its end-of-image marker, or it is treated as unreadable | `BitmapFactory` returns a partly gray image for a truncated JPEG, where Pillow refused it. This keeps the Pi behaviour. Bytes after the end marker are allowed. |
| 4 | UI icons are vector paths drawn in code, not XML vector drawables | Every screen is one canvas, drawn in design pixels. The launcher icon is an XML adaptive icon. |
| 5 | The Frame page is reached by a "More settings" button in the Settings header | There is no mockup for it. It reuses the existing card and row style. The button doesn't appear while a save error is shown. |
| 6 | Text and messages changed for Android | "Set location in Settings" replaces "…config.toml". The empty-folder hint is "Choose a photo folder in Settings" (plan §5). "Your previous settings are still saved" replaces "…on disk". |
| 7 | Dependencies added | datastore-preferences 1.2.1, exifinterface 1.4.2, lifecycle 2.11.0, coroutines 1.11.0, and Robolectric 4.17 for tests. All are plan-listed except Robolectric (see deviation 1). Versions are verified in `verification.md`. |
